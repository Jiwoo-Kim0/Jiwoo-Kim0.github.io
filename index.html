백엔드 · 인프라 개발자

Spring Boot 백엔드와 Docker·Jenkins 기반 인프라를 주로 다룹니다. 장애가 나면 추측보다 로그와 측정으로 원인을 좁히고, 고친 뒤에는 같은 문제가 다시 생기지 않도록 테스트나 배포 단계에 확인 장치를 남기는 편입니다.

SSAFY 15기에서 팀 프로젝트 네 개를 진행했고, 그중 공통 프로젝트 길봄으로 반 1등 우수상을 받았습니다.

요약

  • 도담에서 서버 인프라와 배포 자동화를 혼자 맡았습니다. 배포 전에 임시 컨테이너로 기동을 먼저 확인하도록 바꾼 뒤로는, 잘못된 코드가 두 번 배포될 뻔했지만 서비스 중단 없이 막혔습니다.
  • 부하 테스트 12회와 프로파일링으로 병목이 커넥션 풀이 아니라 CPU라는 것을 확인했고, 코드를 고치지 않고 설정 2건만 바꿔 처리량을 9.4% 올렸습니다.
  • LLM이 금융 수치를 지어내지 못하도록, 답변에 나온 숫자를 서버가 계산한 값과 하나씩 대조해 맞지 않으면 답변을 버리는 검증 단계를 만들었습니다.
  • 길봄에서는 결함 기능을 백엔드부터 화면까지 혼자 맡았고, 모니터링 알람 39개와 암호화 백업, 복원 리허설을 구축했습니다.

배포해도 서비스가 멈추지 않는 파이프라인

  • GitLab에 머지되면 Jenkins가 빌드·테스트·배포까지 자동으로 진행합니다.
  • 운영 컨테이너를 바꾸기 전에 임시 컨테이너를 먼저 띄워 정상 기동을 확인하고, 실패하면 교체하지 않습니다.
  • 배포 후 헬스체크를 두 단계(앱 내부 상태, Nginx를 거친 실제 요청)로 나누고, 실패 시 직전 버전으로 자동 롤백합니다.
  • 이후 환경변수 누락과 DB 타입 불일치가 각각 배포될 뻔했지만 모두 중단 없이 차단됐습니다.

숫자를 지어내지 않는 AI 코치

  • LLM에는 서버가 이미 계산한 진단 결과만 넘기고, 이름·계좌·거래 내역은 애초에 읽지 않도록 했습니다.
  • 답변에 나온 숫자를 서버 값과 대조해 출처 없는 숫자가 하나라도 있으면 답변을 버리고 준비된 문장으로 대신합니다.
  • 같은 질문은 Redis에 저장된 답변으로 돌려줘 응답 시간을 2.29초에서 0.11초로 줄였습니다.
  • 사용자당 시간당 40회로 호출을 제한해 AI 사용료가 갑자기 늘지 않게 했습니다. Redis가 죽어도 제한은 유지됩니다.

측정으로 찾은 병목

  • 처음엔 DB 커넥션 풀이 부족할 거라고 예상했지만, 측정해 보니 CPU가 먼저 97%까지 차고 50초 뒤에야 풀 대기가 생겼습니다.
  • JFR로 CPU 사용처를 보니 직접 작성한 코드는 0.4%뿐이었고, 대부분 프레임워크 쪽이었습니다.
  • 설정 2건(SQL 구문 캐시, 보안 필터 관측 끄기)으로 처리량 +9.4%, 응답 시간 p95 −27%.
  • 22분 동안 100만 건을 보낸 지속 부하 테스트에서 실패 0건이었습니다.

운영과 보안

  • HTTPS, 방화벽, 로그인 요청 횟수 제한, 컨테이너 비루트 실행을 적용했습니다.
  • DB를 매일 백업하고, 임시 DB에 실제로 복구해 보는 리허설까지 했습니다.
  • Prometheus·Grafana·Loki로 지표와 로그를 모으고, 이상이 생기면 팀 메신저로 알림이 가도록 했습니다.

60분 서비스 중단, 그리고 재발 방지

증상

지도 묶음을 누르면 로그인이 풀리던 문제

길봄 · 2026.08

증상
결함 지도에서 묶음을 클릭하면 가끔 로그인 화면으로 튕겼습니다.
시도
요청이 몰려서라고 보고 요청 수를 줄였고, 다음엔 인증 필터를 의심해 고쳤지만 둘 다 원인이 아니었습니다.
전환
추측을 멈추고 원인을 구분할 수 있는 로그부터 심었습니다. 쿠키가 안 왔는지, 왔는데 세션이 없는지를 가를 수 있게 했습니다.
원인
사진을 불러오는 API가 응답마다 새 로그인 쿠키를 내려보내, 사진 여러 장을 동시에 받으면 기존 쿠키가 덮어써지고 있었습니다.
해결
분석 결과와 로그를 담당자들에게 공유해 Nginx에서의 쿠키 차단과 API 수정을 나눠 진행했습니다.

원인
Nginx에 /api/auth/ 경로로 설정했지만 실제 경로는 /api/v1/auth/였습니다.
해결
경로를 고친 뒤 직접 요청을 보내 12번째부터 차단되는 것을 확인했습니다. 설정했다는 것과 동작한다는 것은 다르다는 걸 배웠습니다.

데이터가 늘자 매번 실패로 뜨던 백업

해결
